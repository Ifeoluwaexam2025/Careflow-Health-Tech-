# CareFlow demonstration script

## Prepare

1. Run `npm ci`, then the checks from the README.
2. Run `npm run dev` and use the same printed origin/port throughout the demo.
3. Use invented names and measurements only. A fresh browser profile contains three
   fictional starter patients; a previously used profile restores its own local data.
4. Explain that this is a portfolio prototype with device-local storage, no backend
   and no clinical validation. Do not clear an existing profile just to reset the demo.

## Five-minute walkthrough

1. **Overview:** show real patient/task counts, priority groups and activity. Explain
   that statistics are derived from records, not hardcoded display values.
2. **Create patient:** add “Casey Rivers (fictional)” in room “104”, North Ward.
   The app saves and opens the profile. Show patient notes and edit the room.
3. **General task:** add “Review fictional checklist” with a complete description,
   High priority and an optional future due time.
4. **Observation task:** add “Record fictional temperature”, category Observation.
   Explain the shared creator contract and category-specific concrete factories.
5. **Task details:** open the checklist, read its full description and dates, then edit
   the title or priority. Complete it. Show the completion timestamp and updated counts.
6. **Observation:** record a fictional temperature of 36.8 °C. Open patient
   Observations and show the value/time. No clinical interpretation is provided.
7. **Activity:** show entries generated by the actions just performed.
8. **Task workspace:** search for the edited task, filter Completed/category, then
   reopen it and show that its completion timestamp clears. Explain derived filters.
9. **Refresh:** demonstrate that patients, task edits/status, measurements and activity
   survive. Patient workspace URLs survive refresh; temporary form/tab state need not.
10. **Dashboard:** show the updated counts and click a summary card to open its task
    filter. Navigate among all five main views.
11. **Removal:** show a confirmation and cancel it. Explain that confirmed patient
    removal also removes its related records, while retaining a workspace removal event.
12. **Mobile:** narrow the browser to 390px. Show navigation, readable forms and a
    native dialog. Tables can scroll within their own container without widening the page.

## Explain the engineering

- Normalized IDs keep one task model and one state source.
- Domain functions are independent from React and storage.
- A form submits an action; it saves before React accepts the change.
- Runtime guards protect data loaded from JSON; TypeScript cannot validate storage.
- Migration preserves original keys and IDs, including tasks created before categories.
- Factory Method is intentionally retained for learning; currently a function would suffice.
- Activity reflects actual actions but is not a secure clinical audit trail.

## Reliability examples

Use isolated test data for these demonstrations rather than damaging existing work.

- The automated suite injects write failures: the form stays open, input remains and
  no successful-save message appears.
- The recovery test supplies malformed JSON: editing blocks, original data remains,
  and its raw backup can be downloaded.
- Disconnect the network only after the app loads. Record a fictional observation;
  it saves locally. Reconnect before reload: there is no service worker/app-shell cache.
- The stale-tab test shows ordinary old revisions are rejected rather than silently
  overwriting newer data. Simultaneous tabs are still outside the transaction guarantees.

## Discuss next steps honestly

Additional browser/screen-reader testing, self-hosted fonts, intentional offline
app-shell caching, larger-dataset pagination and a separately designed backend/security
model. No healthcare compliance, clinical safety or real system integration is claimed.
